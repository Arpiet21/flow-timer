# Flow Timer — Project State

1. **Stack**: Vanilla JS + HTML/CSS, hosted on Vercel free, Firebase (Firestore + Auth) for backend, auth via `auth.js`.
2. **Database**: Firebase Firestore only. Tasks at `users/{uid}/tasks/{taskId}`. Plan at `users/{uid}/plan/current`. Sessions at `users/{uid}/sessions/{id}`. Devices at `users/{uid}/devices/{id}`. Scripts at `users/{uid}/scripts/{id}`.
3. **Auth**: Firebase Auth — email/password + Google (signInWithPopup). `firebase-client.js` initializes Firebase app, `_db`, `_auth`. Auth token read from Firebase Auth state, never from localStorage.
4. **Task Manager**: Full CRUD — add/edit/delete/complete tasks with categories, priorities (5 dots), estimated time (up to 2h), scheduled dates, scheduled time (HH:MM), recurring days, subtasks. Optimistic UI with Firestore sync via `_sbInsert/_sbUpdate/_sbDelete`.
5. **Task UI**: Tasks grouped by Today / Tomorrow / Day-after / Upcoming. Each section shows estimated time total. No "Refresh from Cloud" button — Firestore is always live.
6. **Weekly Planner**: Drag-and-drop tasks between days. Drop updates `scheduled_date` in Firestore and re-renders both TaskManager and WeekPlanner.
7. **Categories**: Dynamic reasons per category (unlimited add/delete rows).
8. **Trial/Plan system**: New users get 7-day trial (plan doc created in Firestore on first login). `_normalize()` computes `trialDaysLeft` from `valid_until - now`. Plan repair logic: missing `valid_until` is backfilled on next login.
9. **Coupons**: `TRIAL30` (30-day trial), `FAMILYLIFE` (lifetime pro), `FAMILY100` (1yr pro), `WELCOME50` (50% off), `LAUNCH30` (30% off). All write to Firestore via `api/apply-coupon.js`.
10. **API routes** (Vercel serverless): Firebase Admin SDK. Shared init in `api/_firebase-admin.js`. Routes: `apply-coupon`, `apply-referral`, `verify-payment`, `stripe-webhook`, `weekly-report`, `generate-script`, `generate-goal-suggestions`, `extract-task-from-photo`, `voice-command`. Vercel env vars: `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, `GROK_API_KEY`, `ANTHROPIC_API_KEY`.
11. **Activity Heatmap**: Focus timer and workout sessions stored in Firestore only (`users/{uid}/sessions`). `Auth.logSession(mode, minutes, task)` writes on each session complete. Heatmap reads via `Auth.getHeatmapData(mode)`. No localStorage fallback.
12. **Session History**: `loadHistory()` reads from Firestore via `Auth.getSessions()`. Fields: `mode`, `duration_minutes`, `task`, `completed_at`.
13. **Tabs**: 5 tabs across 2 rows — Row 1: ⏱ Work Timer, 💪 Workout Timer, ✅ Tasks, 🎬 Video. Row 2: 🧘 Meditation (separated by `.mode-tabs-divider`). Mobile: 2×2 grid at ≤640px. `switchTimerType(mode)` handles show/hide of all sections.
14. **Video Creation Tab** (`#video-section`): New tab housing Script Copier. `ScriptCopier.init()` called when switching to Video tab.
15. **Script Copier** (`scripts.js`): Scripts stored at `users/{uid}/scripts/{id}`. Each script has multiple clips (`clips[]` array). Features:
    - Scripts show as collapsed folders — click to expand clips inside
    - Multi-select checkboxes + bulk delete bar (delete multiple scripts at once)
    - Add/edit/delete scripts and individual clips
    - **Import from ChatGPT**: paste JSON → auto-splits into clips. Supports `scenes→clips`, `shots`, `clips`, `frames` array formats.
    - JSON import: `global_style` added as first clip + embedded in every scene/shot clip JSON when copied.
    - Each clip copies as structured JSON: `{ shot_id, duration, motion, mood, prompt, global_style }`.
    - **Float button**: opens Document PiP sticky floating window — stays on top across all tabs.
    - `_uid = user.uid || user.id` (Auth returns `.id` not `.uid`)
16. **Grok Script Generation** (`api/generate-script.js`): Vercel API route that calls `https://api.x.ai/v1/chat/completions` with `grok-3` model. Takes `{ projectName, description, style, duration, shots, model }` and returns structured JSON script. Needs `GROK_API_KEY` in Vercel env vars. UI not yet wired.

    - Task blocks colored by category, height = estimated duration, shows start–end time range
    - Overlap detection — multiple tasks in same slot render in adjacent columns
    - Red "now" line with dot, updates every minute
    - Unscheduled strip at top for tasks with no `scheduled_time`
    - Navigate days with ‹ / › or jump to Today
    - Click empty time slot → switches to List, opens add form with date + time pre-filled (snapped to 15 min)
    - Click task block → opens edit form
    - `DayScheduler.refresh()` called after every task add/edit

    - Task form: 🕐 Time input row appears when a date is selected; clears when date is cleared
    - Deployment: use `vercel --prod` (direct CLI deploy, no GitHub needed)

26. **Hour Certificate** (`js/certificate.js`): Shareable "This hour counted." card generated after every completed Work Timer session ≥ 10 min. Organic-growth/watermark feature — brand line is fixed, not editable.
    - **Spec note**: original spec was written assuming React (`html-to-image` inside a React component, a `/hours` route, a `/dev/certificate` storybook page). This app has no build step, so it was adapted 1:1 in intent: card = a hidden DOM node at fixed pixel size populated via template strings; `html-to-image` loaded via CDN (`unpkg`) and called directly on that node (the library is DOM-based, not React-specific, so no fidelity was lost); `/hours` → static `hours.html` page (same pattern as `blog.html`/`upgrade.html`); the storybook dev page was skipped (no scaffolding exists for it) — test via real session completions instead.
    - **Templates**: Minimal (free tier), Dark (`#0E0E10` + amber accent), Gradient — all 1080×1350 (feed), lazily also exportable at 1080×1920 (Stories) via a `variant` param on the same renderer. No custom web font — app already uses system fonts (`'Segoe UI', system-ui`), which sidesteps the spec's font-loading race entirely; still awaits `document.fonts.ready` before capture as cheap insurance.
    - **Data model**: `users/{uid}/certificates/{id}` — `{ sessionId, createdAt, durationMin, taskTitle, goalTitle, streakDay, userLine, template }`. No PNG stored — image is regenerated on demand from data. Written right after `Auth.logSession()` in `onTimerEnd()` (app.js); caps at 30 most recent per user (older ones batch-deleted on write).
    - **Settings**: "Show certificate after sessions" — Always / Only 60min+ / Never (default Always), stored in the existing `state.settings` localStorage blob alongside `soundType` etc. Template choice (Minimal/Dark/Gradient) also saved there as the user's default.
    - **Share flow**: `navigator.canShare({ files })` → native share sheet with PNG + caption; falls back to PNG download + clipboard-copied caption (iOS Safari's inconsistent file-sharing support is the main reason for the fallback). Caption: `This hour counted. {durationMin} min on {taskTitle}. Day {streakDay}. ⏳ flowtimer.app` with `?utm_source=certificate` on any link.
    - **Premium gating** (pro/trial vs free, same check as elsewhere in the app): free = Minimal template only, no "→ toward: [goal]" cascade line, last 5 in gallery; premium = all 3 templates, cascade line shown when the session's task links to a Goal Cascade goal (no task↔goal link exists in the data model yet, so this is currently always blank — see item 27), last 30 in gallery. Sharing itself is never paywalled.
    - **Hour-milestone cards** (added for Hero Mode, item 30): a 4th card type layered on top of the same rendering pipeline — "🥉 1 Hour of Focus!" / "🥈 10 Hours" / "🥇 100 Hours" / "🏆 1,000 Hours" (bronze/silver/gold/legendary), keyed off `GameLayer.tierForHour()` against a lifetime (uncapped) focus-minutes counter on the Hero Mode profile, not the per-session cert. Always shown, never premium-gated, and takes priority over the routine per-session card for that one completion (never both). See `GAME_LAYER_NOTES.md`.
    - **Phase 2 (not built)**: public `/c/{certId}` OG page for link-sharing, monthly "Wrapped" aggregation, video/animated cards, server-side rendering.
27. **Goal Cascade** (`js/goals.js`, 🎯 Goals tab): 7-level cascade — **Someday → Five-Year → One-Year → Monthly → Weekly → Daily → Right Now**. Each level must answer "so what do I do about it?" for the level above (same lineage as OKR cascading and Hoshin Kanri, applied to one person's life instead of an org) — the test of a real cascade is that any small task traces up to the Someday goal, and the Someday goal traces down to something doable right now. Levels 1-6 are goal statements; level 7 (Right Now) is deliberately different in kind — a single literal next action, not a goal (e.g. "Open the doc and write the scene where..." not "Write more of the book"), reflected in both the AI-suggestion prompt (`api/generate-goal-suggestions.js`) and the "→ Send to Tasks" button, which only appears on level 7.
    - Stored at `users/{uid}/goals/{id}`: `{ level (1-7), title, parent_id, cascade_id }`. Multiple cascades supported — `cascade_id` is the level-1 goal's own doc id; a user can run separate cascades per life domain (career, health, etc.).
    - Renamed from an earlier "Life Vision → 10-Year → 5-Year → 1-Year → Quarterly → Monthly → Weekly" naming (2026-07-19) — that version used different time horizons (10-Year/Quarterly, no Daily/Right Now), not just different labels, so treat any reference to those old names as stale.
28. **AI Task Assistant — photo scan** (`api/extract-task-from-photo.js`): 📷 Scan button next to "Add a task…" in the Tasks tab (`js/tasks.js` → `_scanPhoto`/`_downscaleImage`/`_applyScannedTask`). Uses the **Anthropic Claude API** (not Grok) — `claude-opus-4-8` with vision input + `output_config.format` (`json_schema`) for guaranteed-structured extraction. Flow: user picks/takes a photo (file input has `capture="environment"` for mobile camera) → client downscales to ≤1568px long edge JPEG via canvas → POSTs `{ image, mediaType, corrections }` to the API route → route returns `{ title, category, priority, estimated_minutes, scheduled_date, scheduled_time, details }` → front end pre-fills the existing Add Task form (never auto-saves — user always reviews/edits before hitting Add). A date/time found in the photo maps to **Schedule** (`task-date-input`/`task-time-input`), not **Given** (which stays defaulted to today, per the Given-vs-Schedule distinction in item 22) — a note's date is a deadline to plan around, not the day the task was handed to you. Extracted `category` only auto-selects if it case-insensitively matches an existing user category; never auto-creates a new category. Needs `ANTHROPIC_API_KEY` in Vercel env vars.
    - **Scan history + correction learning** (`Auth.createScanHistory`/`finalizeScanHistory`/`getScanCorrections` in `auth.js`, `users/{uid}/scan_history/{id}`): stores only the AI's extracted guess + (once saved) what the user actually kept — no photo is stored (would need the paid Firebase Blaze/Storage plan, deliberately out of scope). On submit, `TaskManager._computeCorrections()` diffs the guess vs. the final task and writes any changed fields as `corrections: [{field, from, to}]`. Before each new scan, the client pulls the last ~8 corrected entries (`Auth.getScanCorrections`) and sends them as a `corrections` hint on the request; the API route folds them into the system prompt as a soft personalization signal. This is **not** real model fine-tuning (Claude's API has no self-serve fine-tuning) — it's in-context few-shot nudging from the user's own correction history, capped at 12 entries to bound prompt size. Capped at 50 most recent history docs per user (older ones batch-deleted on write, same pattern as certificates). A `source` field (`'photo'`|`'voice'`) tags each entry — both modalities currently draw from the same combined correction pool.
29. **AI Voice Assistant** (`api/voice-command.js`, `js/voice-assistant.js`): 🎤 floating mic button, fixed bottom-right, visible on every tab (not just Tasks). **Claude-only, no separate STT provider**: speech-to-text runs entirely client-side via the browser's free built-in **Web Speech API** (`SpeechRecognition`/`webkitSpeechRecognition`) — no audio is ever uploaded. Only the resulting transcript text is sent to **Claude** (`claude-opus-4-8`, `output_config.format` json_schema) to classify intent. (Earlier version used OpenAI Whisper server-side per an explicit ask for "real Whisper," then was replaced with this free browser-native approach once cost/vendor tradeoffs were reconsidered — no `OPENAI_API_KEY` needed.) Needs `ANTHROPIC_API_KEY` in Vercel env vars (already required for item 28).
    - **Browser support caveat**: `SpeechRecognition` is well-supported in Chrome/Edge/Chrome-Android; Firefox has no support and Safari's is inconsistent across versions — the mic button feature-detects and hides itself entirely (`display:none`) when the API is absent, rather than showing a broken control.
    - **Flow**: tap mic → `SpeechRecognition.start()` listens once (`continuous:false`) → on a result, client sends `{ transcript, history }` to the route → route asks Claude to return `{ intent, clarifying_question, task, timer }` where `intent` is one of `add_task` / `start_timer` / `stop_timer` / `clarify`.
    - **`add_task`**: routed through the exact same `TaskManager._applyScannedTask()` pre-fill path as the photo scanner (item 28) — never auto-saves, same review-before-Add guarantee, same `scan_history`/corrections pipeline (tagged `source: 'voice'`).
    - **`start_timer`/`stop_timer`**: `voiceStartTimer(mode, minutes, label)`/`voiceStopTimer()` helpers in `app.js`. `mode: 'work'` (default) sets a one-off `state.totalTime`/`state.timeLeft` directly (does **not** overwrite the user's saved default `state.settings.work` duration) and calls the existing `startTimer()`. `mode: 'workout'` just calls `switchTimerType('workout')` + the existing `woStart()`/`woPause()` from `workout.js` as-is — the HIIT timer's interval structure (rounds/work-secs/rest-secs) doesn't map to a single spoken duration, so a duration mentioned in a workout command is currently ignored. `voiceStopTimer()` has no mode input from the model; it just pauses whichever of Work Timer / Workout Timer is actually running.
    - **Clarifying-question loop**: the API is instructed to default aggressively (25 min, priority 3, category "General", mode "work") and only return `intent: "clarify"` when something is truly unrecoverable (e.g. ambiguous between add-task/start-timer, or unintelligible). On `clarify`, the client speaks the question via `SpeechSynthesisUtterance`, toasts it, and auto-resumes listening after ~1.2s (no new user gesture needed — mic permission was already granted this session) — the running `_history` array of `{role, text}` turns is sent back on the follow-up so Claude has full context. History resets on any actionable intent.
30. **Hero Mode — gamification layer** (`js/hero.js` engine + `js/hero-ui.js` UI, 🎮 header icon — files are named `hero*.js`, not `game*.js`: corporate firewalls commonly block asset URLs containing "game", which silently broke the feature for some users before the rename). SuperBetter-style XP/levels/streaks/power-ups/bad guys/rewards on top of existing focus/task/goal events. Adapted from a React-flavored spec onto this vanilla-JS/Firebase-compat stack — full list of adaptation decisions in `GAME_LAYER_NOTES.md`; summary below.
    - **Two currencies**: XP only goes up and drives levels (never spent). Coins earned 1:1 with XP, spent in the Rewards Shop (never reduces XP/level). All rules/caps/multipliers centralized in `GameLayer.rules` (`js/hero.js`).
    - **Levels**: `xpForLevel(L) = 100*(L-1) + 25*(L-1)*(L-2)` (100/150/200/… XP per level). Titles: 1-4 Apprentice, 5-9 Focused, 10-14 Builder, 15-19 Craftsman, 20-29 Master, 30+ Legend.
    - **XP sources**: focus minutes (1 XP/min, capped 480/day) + session bonus (+10 for ≥20min, counts as a Quest) hooked into `_processTimerEnd()`'s work branch in `app.js` (same point `Auth.logSession`/`Certificate.onSessionComplete` already fire — pagehide partial-credit sessions never earn XP). Tasks (10/25/50 XP by new `size` field on the task, default `'small'`; ×1.5 if `linked_goal_id` matches the pinned Current Challenge's cascade) hooked into `TaskManager.toggleComplete()`. Goals (20/75/250/1000/3000 XP for Daily/Weekly/Monthly/One-Year/Five-Year; Monthly/One-Year/Five-Year trigger the Epic Win modal) hooked into a new complete/reopen toggle added to each Goal Cascade level row (`js/goals.js` — goal completion didn't exist before this). Power-ups (5 XP, max 8/day) and Bad Guy battles (15 XP, max 3/day) from the 🎮 panel. SuperBetter Day (+50 XP, once/day) auto-fires when ≥3 power-ups + ≥1 battle + ≥1 quest are logged in the same local-calendar day.
    - **Idempotency**: every award/revoke is a Firestore transaction (`_db.runTransaction`, compat SDK) keyed by a deterministic ledger doc id (`task_{id}`, `session_{id}`, `powerup_{id}_{dayKey}`, `battle_{id}`, `sbday_{dayKey}`, `goal_{id}`, `streak_{n}_{dayKey}`) under `users/{uid}/xpLedger/{eventId}` — double-taps/refreshes/offline retries are safe no-ops. Each ledger doc also stores the exact `gameDays` delta it applied so `revoke()` can reverse it precisely (not in the original spec's schema — see notes).
    - **Streaks**: `users/{uid}/game/profile` tracks `currentStreak`/`longestStreak`/`freezes` (max 2, earned every 7-day streak multiple). `GameLayer.evaluateDay()` runs at app boot and after every award, lazily backfilling any gap days since `lastEvaluatedDayKey` (idempotent, no scheduled job — this app has none anywhere). Day boundaries use the **browser's local** calendar date (`GameLayer.dayKey()`), intentionally different from the rest of the app's UTC-based `todayStr()`.
    - **UI**: always-visible HUD bar (identity/level/XP bar/streak/coins) sits between `<header>` and `<main>` — outside `switchTimerType()`'s 8 toggled tab sections, so it's visible on every tab with zero extra wiring (same trick as the voice-assistant mic button). Quest Board / power-up chips / Current Challenge banner live inside the Work Timer tab (`#flow-section`) only. Power-ups/Bad Guys/Shop/Stats/Secret Identity management lives behind the 🎮 header icon in a tabbed modal (not a 9th main tab — the existing tab bar is already 8 buttons across 2 rows). One-time 3-step onboarding wizard (`#hero-wizard-modal`) gated by `profile.onboarded` in Firestore (not localStorage, so it's shared across every device the same account logs into, not re-asked per browser — see GAME_LAYER_NOTES.md); "Hero Mode" toggle in Settings just hides the HUD, data is kept either way.
    - **Data model**: `users/{uid}/game/profile` (single doc), `xpLedger/{eventId}`, `gameDays/{dayKey}`, `powerups/{id}`, `badGuys/{id}`, `battles/{id}`, `rewards/{id}`, `redemptions/{id}`. No `firestore.rules` file exists anywhere in this repo (confirmed for every other collection too) — rules for these collections need to be added directly in the Firebase Console; see `GAME_LAYER_NOTES.md` for the exact rule to paste.
    - **Out of scope for v1** (per spec): leaderboards/social, AI-generated quests, badges beyond levels/streaks, server-side award validation, retroactive XP for past activity.
    - **v1.1 — scheduled power-ups + Boss HP** (added after initial build): power-ups got an optional `recurring_days` field (0=Sun…6=Sat, same convention as tasks; unset = every day) — the Work Timer chip row only shows today's scheduled ones, and each row in the 🎮 panel shows a 14-day done/missed/unscheduled dot strip. Bad guys got `maxHp`/`currentHp`/`defeatedCount`; one can be pinned "active" (`profile.activeBadGuyId`) and takes passive damage from every completed task/qualifying focus session/power-up, while the "Battled it" button always damages whichever bad guy was clicked (harder hit) regardless of active status. Reaching 0 HP awards a one-time +100 XP "Demon Defeated!" toast via its own idempotent ledger entry, then resets HP so the same bad guy can be fought again. Boss HP damage is deliberately **not** reversed if the triggering task/session/power-up is later un-completed (XP/coins still are) — see `GAME_LAYER_NOTES.md` for why.
